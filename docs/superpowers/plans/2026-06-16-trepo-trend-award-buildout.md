# Trepoトレンド大賞2026 オペレーション構築 実行計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **注:** 本計画はコード実装ではなく業務オペレーションの構築。各タスクの「検証」は、成果物が設計書（`docs/superpowers/specs/2026-06-16-trepo-trend-award-selection-design.md`）と一致するかの突合で行う。

**Goal:** Trepoトレンド大賞2026の「エントリー収集」と「トレンド選出」を、編集部が当日から運用できる具体オペレーション（候補プールDB・スコアカード・フォーム・審査手順）として構築する。

**Architecture:** オファー型リサーチとインバウンドを単一の候補プールDBに合流させ、0次→1次（スコアカード）→2次（お試し会）→3次（審査員）の4段階で選出。実績×主観50:50のエビデンス必須スコアカードを審査の中核に置く。

**Tech Stack:** Notion（候補プールDB・手順書）/ スプレッドシート（スコアカード採点シート）/ Googleフォーム（エントリーフォーム）。一部はNotion APIで構築可能。

**前提となる確定事項（設計書 §1 より）:** 権威性最優先 / 編集部リサーチ＋インバウンド / 実績×主観バランス（予兆型は対象外）/ A×Cハイブリッド / エビデンス必須5段階 / 該当項目のみ正規化 / 実績:編集=50:50。

## Task 3: 候補プールDB（Notion）を構築する

オファー型とインバウンドを合流させる単一DB。Notion APIで作成可能。

**成果物:** Notion DB「Trepoトレンド大賞2026 候補プール」

- [ ] **Step 1: DBプロパティを定義**

```
- 対象名（title）
- 流入経路（select: 編集部リサーチ / インバウンド）
- カテゴリ（select: コスメ/スキンケア/.../その他 ※フォームと同一）
- エントリー条件（select: a上半期 / b下半期）
- 企業名（rich_text）
- 担当者・連絡先（rich_text）
- 商品/サービスURL（url）
- 価格（rich_text）
- 概要（rich_text）
- トレンドポイント（rich_text）
- ── 実績スコア素材（エビデンスは各リンク欄に） ──
- SNS話題量_点（number 1-5）/ SNS_根拠（url or rich_text）
- 売上実績_点（number 1-5）/ 売上_根拠
- メディア掲載_点（number 1-5）/ メディア_根拠
- 検索の伸び_点（number 1-5）/ 検索_根拠
- インフル反響_点（number 1-5）/ インフル_根拠
- 実績スコア（formula: 該当項目のみ正規化、§3.2の式）
- ── 編集評価 ──
- 今年らしさ_点 / Z世代親和性_点 / ストーリー性_点 / 推し度_点（number 1-5）
- 編集評価コメント（rich_text）
- 編集評価スコア（formula: 合計÷20×100）
- 総合スコア（formula: 実績×0.5 + 編集×0.5）
- ── 審査進捗 ──
- 形式要件（select: OK / 対象外）
- 段階（select: 0次/1次通過/2次お試し会/3次/受賞/落選）
- お試し会評価（rich_text）※2次の当事者検証レイヤー（1次スコアには混ぜない）
```

- [ ] **Step 2: 実績スコアのformulaを実装**

該当項目（N/A=空欄を除外）の平均×20。空欄を除外して平均を取るNotion formulaを記述（例: 入力された点数の合計 ÷ 入力された項目数 × 20）。

- [ ] **Step 3: DBを作成**

Notion API（`POST /v1/databases`）でCreative Groupワークスペースに作成。親ページは「Trepoトレンド大賞2026」配下とする（page id: `3812a9c9-20f7-80ba-9bc6-cdd2ac24241f`）。

- [ ] **Step 4: テストレコードで検証**

ダミー候補を1件入力し、§3.2の計算例（SNS5/メディア4/検索3、売上・インフルN/A → 実績80点）が再現されるか確認。総合スコアが `実績×0.5+編集×0.5` で出るか確認。

- [ ] **Step 5: 完了報告**

## Task 4: スコアカード採点シートを設計する

複数編集者（2〜3名）採点→平均の運用を支えるシート。Notion DBで完結しない「採点者ごとの記録→平均」部分を担う。

**成果物:** `docs/superpowers/specs/trepo-award-scorecard-sheet.md`（シート構成仕様）

- [ ] **Step 1: シート構成を定義**

```
1候補 = 1ブロック。採点者列を2〜3名分用意。
行: 5実績項目 + 4編集項目、各行に[点数]と[根拠/コメント]列。
集計行:
  - 実績スコア = 採点者ごとに該当項目のみ正規化 → 採点者間で平均
  - 編集評価スコア = 採点者ごとに合計÷20×100 → 採点者間で平均
  - 総合スコア = 実績平均×0.5 + 編集平均×0.5
カテゴリ別の総合スコア降順ランキングシートを別タブに用意。
```

- [ ] **Step 2: エビデンス必須ルールを明記**

実績5項目は、点数を入れる場合は根拠列の記入を必須とする旨をシート冒頭に明記。根拠が空の点数は無効（採点やり直し）。

- [ ] **Step 3: 検証**

設計書 §3.2/§3.4 と突合: ①該当項目のみ正規化になっているか ②50:50か ③複数採点者平均になっているか ④エビデンス必須が明記されているか。

- [ ] **Step 1: 0次（形式要件）チェックリスト**

```
□ 対象外カテゴリでないか（医薬品/医療行為/サロン・クリニック専売/体験のみ完結）

```

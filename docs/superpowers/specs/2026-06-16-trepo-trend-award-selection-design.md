- 作成日: 2026-06-16
- 対象企画: Trepoトレンド大賞2026（主催: Trepo編集部 / 株式会社Creative Group）
- 本書の範囲: ①エントリー（ノミネート候補）の集め方、②「トレンド」の定義と選出ロジック
- Notion出典: 「Trepoトレンド大賞2026」社内企画メモ・リリース案・スケジュール（仮）

## 1. 設計の前提（確定済みの方針）

ブレスト合意により、以下を本企画の基本方針として固定する。

| 論点 | 決定 |
|---|---|
| 賞の性格 | **権威性・編集力を最優先**。マネタイズは数年かけて信用を積み、権威が確立したタイミングで作る（1年目は収益設計を切り離す） |
| 企業の集め方（主エンジン） | **編集部リサーチ型（オファー）をメイン**、**プレスリリース経由のインバウンドを補助**。既存取引先への営業・コールド一斉送信は「身内・出来レース感」回避のため主軸にしない |
| トレンドの定義 | **「2026年に実際に話題になった実績」×「編集部のトレンド観（主観）」のバランス**。予兆型（これから伸びる）は今回の趣旨と異なるため対象外 |
| 選出ロジックの大枠 | **A×Cハイブリッド**: 段階フロー（A）の中で、1次審査にスコアカード（C）を組み込む |
| 実績スコアの採点方式 | **エビデンス必須の5段階**（各点に根拠リンク/数値/スクショの添付を必須化） |
| 該当しない実績項目の扱い | **該当項目のみで正規化**（N/Aは集計から除外） |
| 実績 : 編集評価の重み | **50 : 50** |

## 2. ① エントリー企業（ノミネート候補）の集め方

### 2.1 基本構造: 単一の候補プールに合流させる

オファー型もインバウンド型も、**同じ1つの「候補プールDB」**に集約する。これにより選出フローを一本化し、両者を同一基準で審査できる。

```
リサーチ期間 6/18(木)〜8/31(月)
┌──────────────────────────────────────────────┐
│  候補プールDB（Notion または スプレッドシート）        │
│                                                 │
│  ▶ 編集部リサーチ型（メイン）                       │
│     SNS(TikTok/IG)・検索トレンド・ECランキング・      │
│     他媒体掲載・インフルエンサー言及 を日常観測          │
│     → 候補として追加し、実績シグナルを記録              │
│                                                 │
│  ▶ プレスリリース経由インバウンド（補助）               │
│     PR配信 → エントリーフォーム応募 → 同DBに合流        │
└──────────────────────────────────────────────┘
```

### 2.2 編集部リサーチの運用原則

- 「ゼロから探す」のではなく、**先に実績シグナルの記録フォーマット（＝3.2のスコアカード項目）を決め、観測しながらそのまま採点素材を蓄積する**。
- リサーチソース: TikTok / Instagram の話題量・保存・ハッシュタグ、Googleトレンド（検索の伸び）、EC・小売ランキング、他媒体掲載、インフルエンサー言及。
- Trepoは既にトレンドメディアを運営しているため、日常の編集観測を候補プールに転記する運用で素地を活かす。

### 2.3 インバウンドの位置づけ

- プレスリリース（リリース案）を配信し、フォーム経由の自発的エントリーを受ける。
- 1年目は知名度不足でインバウンド母数は読めないため、**あくまで補助**。母集団の質はリサーチ型で担保する。

### 2.4 オファー対象への企業連絡

- ノミネート候補に挙がった対象の企業へ連絡し、商品サンプル・画像素材・関連資料の提供を依頼（スケジュールの「企業連絡＆商品取寄せ 9/11〜9/25」と整合）。

## 3. ② トレンドの定義と選出ロジック

### 3.1 4段階フロー（A×Cハイブリッド）

既存スケジュールの3段階審査を踏襲し、その前段に「候補プール化（0次）」を置く。

| 段階 | 担当 | やること | 効かせる軸 | 時期目安 |
|---|---|---|---|---|
| **0次** 候補プール化 | 編集部 | リサーチ＆インバウンドを合流／形式要件チェック（対象外カテゴリ除外） | — | 〜8/31 |
| **1次** スコアリング | 編集部 | スコアカードでノミネート選定（カテゴリ別上位） | **実績 × 主観** | 〜9月中旬 |
| **2次** お試し会 | Trepoガールズ | 実際に体験し、読者リアル評価点を付与 | **当事者検証** | 9/28・29 |
| **3次** 最終審査 | 審査員 | 順位・大賞を決定 | **主観（権威）** | 10月上旬 |

- **0次の形式要件除外**: 医薬品、医療行為を伴うもの、サロン・クリニック専売品、体験のみで完結するサービス、掲載が難しい表現を含むもの、Trepo読者層との親和性が著しく低いもの、極端に高額で読者に非現実的なもの。

### 3.2 1次審査スコアカード（核心）

#### A. 実績スコア（客観・エビデンス必須・該当項目のみ正規化）

各項目を1〜5点で採点し、**各点に根拠（リンク/数値/スクショ）の添付を必須**とする。該当しない項目はN/A（集計から除外）。

| 実績シグナル | 配点 | 根拠例 |
|---|---|---|
| SNS話題量 | 1-5 / N/A | TikTok/IG言及数・保存・ハッシュタグのスクショ |
| 売上・販売実績 | 1-5 / N/A | 売り切れ・ランキング入りの証拠 |
| メディア掲載 | 1-5 / N/A | 掲載URL一覧 |
| 検索の伸び | 1-5 / N/A | Googleトレンドのグラフ |
| インフルエンサー反響 | 1-5 / N/A | 言及投稿のリンク |

**計算式:**
```
実績スコア = (該当項目の合計点 ÷ 該当項目数) × 20   … 100点換算
```
> 計算例: SNS=5・売上=N/A・メディア=4・検索=3・インフル=N/A
> → (5 + 4 + 3) ÷ 3 × 20 = **80点**

#### B. 編集評価スコア（主観・各項目に一言コメント必須）

| 評価項目 | 配点 |
|---|---|
| 今年らしさ（2026年Z世代の気分の象徴性） | 1-5 |
| Z世代・女子大生との親和性 | 1-5 |
| ストーリー性・記事化しやすさ | 1-5 |
| 編集部の"推し"度 | 1-5 |

**計算式:**
```
編集評価スコア = (合計点 ÷ 20) × 100   … 100点換算
```

#### 総合スコア（実績 : 編集 = 50 : 50）

```
総合スコア = 実績スコア × 0.5 + 編集評価スコア × 0.5
```

→ **カテゴリ別にランキングし、上位をノミネート確定**。

### 3.3 2次・3次の扱い

- **2次（お試し会）**: Trepoガールズの読者評価は、実績・編集とは別の **「当事者検証レイヤー」** として記録し、**1次スコアには混ぜず3次審査に持ち込む**。
- **3次（審査員）**: 1次総合スコア・お試し会の読者評価・審査員の評を統合して、最終順位および大賞を決定する。

### 3.4 運用ルール（権威性の担保）

- 1次スコアカードは **複数編集者（2〜3名）で採点 → 平均** をとり、個人バイアスを薄める。
- 重み（50:50）・採点基準・各年の判断根拠は **「企画資産」として記録** し、毎年見直し可能にする。
- 1年目はエビデンス必須5段階で運用し、蓄積データをもとに**2年目以降の定量しきい値化**を目指す。

## 4. ③ 定義整合のための調整（予兆型の排除）

トレンドの定義を「実績 × 主観」に固定した結果、現行ドキュメントに残る**予兆型の要素**は整合しないため、以下を整理対象とする。

| 対象 | 現状 | 調整方針 |
|---|---|---|
| フォーム条件 b | 「2026年下半期以降に売っていきたい・話題にしたいもの」 | 「2026年に話題になった/売れた（上半期・下半期問わず）」に統合し、実績型に寄せる |
| フォーム条件 c | 「a・bに該当しないがエントリーしたい強い理由がある」 | 予兆・例外枠として残すか要再検討（権威性重視なら縮小）|
| 受賞ジャンル「ネクストブレイク大賞」 | 予兆型（今後ブレイクしそう） | 実績型の「ベスト新商品賞」に統合、または削除 |

> 注: 発表が12/15のため、2026年下半期（7〜12月）に話題化したものも「実績」として正当に対象に含まれる。「これから（来年以降）売りたい」という未来志向のみを排除する。

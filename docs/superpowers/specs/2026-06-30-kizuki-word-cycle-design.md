# 気づきワードサイクル — 設計仕様書

作成日: 2026-06-30
ステータス: 設計確定（実装計画はこの後 writing-plans で作成）

## 背景・狙い

資生堂が輸入販売する化粧品ブランド「アベンヌ」のマーケティング責任者から共有された施策をヒントにする。ブランドが消費者と直接会話する中で気づく訴求点（「気づきワード」）を量産し、広告でサイクルを回す手法を、CGのパッケージサービスに組み込む。

CGでは、口コミサービス **Pamun**・**広告運用**・**インフルエンサー施策（診断ツール）** の3つを1本のループに束ねる施策になる。

施策の元になる4ステップ：

1. **勉強会**：美容感度の高いユーザー／マイクロインフルエンサーに商品提供→アンケート→ブランド担当者との座談会。薬機法を気にせず本音を引き出し、ブランドが気づいていない訴求点を抽出。お土産サンプルでオーガニック投稿も獲得。
2. **モニター（レビュー）施策**：気づきワードからオリエンシートを作りPamunでレビュー量産→広告で使えそうなクリエイティブ候補を選定。
3. **モニター投稿の2次利用で広告運用**：実配信データで刺さる訴求・画像を選出し、相性の良いデモグラも抽出。
4. **勝ちデータ起点でインフルエンサー選定・コラボ**：勝ち訴求・勝ちデモグラを診断ツールに投入し、相性の良いミドル/メガインフルエンサーを精度高く選定・コラボ。

## 設計方針（確定事項）

- **ゴール**：パッケージ設計を主、データ構造も合わせて。両方を段階的に進める。
- **販売単位**：ステップ別のモジュール販売（入口を作りやすく横展開で上げる）。ただしデータ連携は密に行う。
- **データの背骨**：まずスプレッド/GAS で回し、スキーマは将来 BigQuery 移行可能な形にしておく。
- **連携アプローチ**：採用＝A案「気づきワード台帳（スコアリング台帳型）」。CGがインフルエンサー診断で確立した「勝ち訴求を実データで選ぶ・虚栄に騙されない」哲学を、訴求ワードにも適用する。

## アーキテクチャ

### データモデル（連携の背骨）

中心テーブル＋4シグナルテーブルの計5テーブル。`word_id` が全モジュールを貫く連携キー。各シグナルは各モジュールが独立して追記できる（＝モジュール単体販売でも台帳が埋まる）。全テーブルは「1行＝1事実」で、そのまま BigQuery のファクトテーブルに昇格できる形にする。

**1. 気づきワード台帳（insight_words）** — 1行＝1ワード（案件×商品単位）
- `word_id`（PK）
- `案件ID`（FK → 案件DB）
- `商品ID`（FK）
- ワード本文
- 訴求軸タグ（効能／情緒／使用シーン／成分／価格 など）
- 起点（勉強会／レビュー／コメント）
- status（候補 → モニター → 広告検証 → 勝ち／見送り）
- 訴求スコア（計算列）
- 確度ステージ（暫定／レビュー反映／広告確定）

**2. 勉強会シグナル（workshop_signals）** — ①勉強会
- `word_id`（FK）・参加者ID（匿名）・発言抜粋・言及数・アンケート評価・ブランド未認知フラグ

**3. モニターシグナル（review_signals）** — ②Pamun
- `word_id`（FK）・レビュー件数・購買意向共感率・代表クリエイティブURL・2次利用可否

**4. 広告シグナル（ad_signals）** — ③広告運用
- `word_id`（FK）・`creative_id`（PK）・CTR・CVR・ROAS・勝ちデモグラ（年代／性別／興味）・配信額

**5. コラボ実績（collab_results）** — ④インフルエンサー診断
- `word_id`（FK）・`influencer_id`（FK）・適合スコア・実売・ROAS

**既存資産への接続**：`案件ID` で案件DB、`案件ID × influencer_id` で提案ログDB／実績タブ、勝ち訴求・勝ちデモグラを診断ツールの M01／M02／M04 の入力に流す。

### 訴求スコアの計算ロジック

100点満点＋虚栄控除。実データ（広告CTR/CVR）を最重視し、言及の多さ（虚栄）だけでは上がらない。診断ツールの原則を移植する。

| モジュール | 何を見るか | 配点 |
|---|---|---|
| ①勉強会 | 言及の質 ＋ ブランド未認知ボーナス（既知より未知の訴求を高く） | 15 |
| ②Pamun | 購買意向共感率（「買いたい/使ってみたい」系 ÷ 総反応。虚栄反応は除外） | 25 |
| ③広告 ★核 | CTR・CVR・ROAS（2次利用クリエイティブの実配信データ。最重視） | 40 |
| ③広告 | デモグラ明確度（刺さる層が立っているか＝後工程のインフル選定精度に直結） | 10 |
| ④インフル | コラボ適合・実売（その訴求でのコラボが実際に売れたか） | 10 |
| 虚栄控除 | 言及/反応は多いのにCVRが基準割れ → 減点（「パケ可愛い」型を弾く） | -20〜0 |

**確度ステージ**（診断ツールのTier思想と同じ。未確認の軸は配点50%＝中央値を初期値）：
- 暫定（勉強会のみ）→ レビュー反映（＋Pamun）→ 広告確定（＋実配信データ＝"勝ち訴求"確定）

**過学習防止ルール（診断ツールから継承）**：
- 各ワードの個別実績は即座にそのワードのスコアへ反映してOK（A：個別実績）
- 配点そのもの（重み）は十分なサンプルが貯まるまで変えない（B：モデル変更は要n数）
- 未確認の軸は中央値（配点50%）を初期値に。データが来たら上書き

**計算例**：
- 「パケが可愛い」＝勉強会11件（高）・購買意向共感12%（低）・広告CTR0.6%（低）→ 虚栄控除発動で **28点 ×**
- 「乾燥でゆらいだ日の駆け込み」＝言及8件・共感62%・CTR2.1%・デモグラ30代敏感肌が明確 → **87点 ◎**

## パッケージ構成（売り方と連携担保）

3モジュールはそれぞれ単体販売。だが全モジュールが同じ気づきワード台帳に読み書きする契約のため、買い足すほど連携が効く。

### モジュールA：気づきワード抽出（入口商品＝勉強会＋Pamunモニター）
- やること：勉強会で本音抽出 → 気づきワード化 → オリエンシート化 → Pamunでモニター・レビュー量産
- 単体の納品物：スコア付き気づきワードリスト（暫定〜レビュー反映）＋2次利用可クリエイティブ
- 台帳へ書く：気づきワード台帳・勉強会/モニターシグナル
- アップセル：「この訴求、広告で確定させましょう」→ B へ

### モジュールB：勝ち訴求広告運用
- やること：2次利用クリエイティブを配信 → 刺さる訴求/画像を実データで選出 → 勝ちデモグラ抽出
- 単体の納品物：勝ち訴求・勝ち画像・勝ちデモグラのレポート（広告確定スコア）
- 台帳へ書く：広告シグナル（CTR/CVR/ROAS/デモグラ）→ スコア確定
- アップセル：「この勝ちデータで最適なインフルを」→ C へ

### モジュールC：相性インフルコラボ
- やること：勝ち訴求・勝ちデモグラを診断ツール（M01/M02/M04）に投入 → 相性の良いミドル/メガ選定 → コラボ
- 単体の納品物：診断スコア付き起用リスト＋コラボ実行＋ROAS回収
- 台帳へ書く：コラボ実績（適合・実売・ROAS）→ 提案ログDB／実績タブへ
- ループ：新たな購買コメントが次回の気づきワード候補へ還流

### 連携担保の仕掛け（単体でも売れるのに連携が切れない理由）
1. どのモジュールも契約・オリエンに「気づきワード台帳への記入」を標準工程として組み込む（台帳はCGが保有・運用）
2. 単体購入でも顧客はスコア付きリストを受け取る → 未確定スコアそのものが次モジュールへの自然なアップセルフックになる
3. `word_id` で串刺しなので、後から別モジュールを足すと同じワードに証拠が積み増し＝CG社内グロースハックの「横展開率」が数字で見える

## 既存資産への載せ方

- 新規 `CG_気づきワード台帳.gs`（既存の `CG_案件データベース.gs` / `CG_提案ログDB.gs` と同じ作法で生成）
- コックピットに「気づきワード」タブ追加（台帳閲覧・スコア表示・診断タブへ勝ち訴求/デモグラを受け渡し）
- `案件ID` で案件DB、`案件ID × influencer_id` で提案ログDB／実績タブと接続。スキーマはBQファクトテーブル互換

## KPI（二層グロースハック）

`project-growth-hack-architecture` の方針どおり、CG社内軸とクライアント成果軸を分離する。

### CG社内グロースハック軸
- モジュール別 商談化率／受注率／粗利
- 横展開率（A→B→C への引き上げ率）
- 1社あたり売上の増加
- 気づきワード → 勝ち訴求 転換率
- 高粗利モジュールの見極め

### クライアント成果軸
- 勝ち訴求の発見数／確定数
- 広告ROAS・CVR改善
- コラボROAS（成果連動契約を推奨）
- レビュー/UGC・指名検索の増加
- 次回商戦で再現できる訴求パターン

## 実装フェーズ（段階的）

- **Phase 1**：台帳GAS＋5シグナルを手入力で回す。スコア計算式を実装。まず1案件で実証。
- **Phase 2**：コックピットに気づきワードタブ＋診断ツール接続（勝ちデータを M01/M02/M04 へ）。
- **Phase 3**：広告/Pamunデータ取込を自動化 → BigQuery昇格 → スコア自動更新。

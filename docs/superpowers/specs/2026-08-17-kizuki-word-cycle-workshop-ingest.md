# 気づきワードサイクル — 勉強会アンケート取込 設計書

作成: 2026-08-17
関連: [Track A取込](2026-08-16-kizuki-word-cycle-tracka-ingest.md) / [Phase3スライス2](2026-07-16-kizuki-word-cycle-phase3-slice2-pamun-ingest.md)

## なぜ作るか

設計上、気づきワードの**起点は勉強会**。しかし第1号（アベンヌ ミルキープロテクターUV）は
勉強会前だったため、Pamun の自由記述から候補ワードを起こした。抽出と採点が同じ22人になり、
共感率は「その22人の中での普及率」以上の意味を持たない状態だった。

2026-08-22 のアベンヌ勉強会で本来の起点が使えるようになる。そこから
**候補ワードと勉強会シグナルを起こす導線**を用意する。

## 前提の訂正

勉強会フォームの【購入意向】【推奨意向】は**商品全体に対する1問**であり、ワード単位ではない。
したがってワードごとの購買意向共感率はこのフォームからは出ない。
**per-word の意向は Track A が担う。** 勉強会が担うのは候補ワードの発掘と勉強会シグナル。

スコアエンジンが勉強会シグナルから使うのは `言及数` と `ブランド未認知` の2つだけ
（`score.js:37` の `workshopScore`）。`発言抜粋` `参加者ID(匿名)` `アンケ評価` は
人が根拠を追うための列で、採点には入らない。

## 入力

**事後アンケート**（`【2026/8_アベンヌ勉強会】事後アンケート（回答）`）の自由記述4問:

| 設問 | 用途 |
|---|---|
| 【印象に残った言葉】 | 気づきワードの主源泉 |
| 【最も印象が変わった点】 | 認識変化 |
| 【説明後に初めて理解できたこと】 | 認識変化 |
| 【使いたい部位・場面】 | 使用シーン軸 |

**事前アンケート**（`…事前アンケート（回答）`）の認知度設問 → `ブランド未認知` の判定材料。
突合キーは**メールアドレス**。

## 決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| 出力範囲 | **候補ワード＋勉強会シグナルの両方** | 同じLLM呼び出しで両方取れる。言及数が入るので勉強会だけでもスコアが0にならない |
| 勉強会シグナルの粒度 | **ワード単位1行** | `aggregateSignals` は同一word_idの `ブランド未認知` を `some()` で OR する。ワード×参加者の行にすると20人中1人でも未認知でTRUEになり、workshopスコアの重みの半分が全ワードで満点になって弁別力を失う |
| ブランド未認知の判定 | **言及者の過半が事前に未認知** | フラグが弁別力を保つ。ちょうど半分は未認知としない（2人中1人はFALSE、3人中2人はTRUE） |
| 人のレビュー | **中間JSONを挟む** | 文言を随時直す運用のため、登録前に編集できる形にする |

## アーキテクチャ

```
事後アンケート（自由記述4問）─┐
                              ├→ workshop_extract.js → candidates.json（人が編集可）
事前アンケート（認知度）───────┘                            │
                                                            ↓
                                        workshop_seed.js → 気づきワード台帳
                                                           ＋ 勉強会シグナル
```

## 構成要素

### `lib/kizuki/workshop-ingest.js`（純粋関数・新規）

| 関数 | 責務 |
|---|---|
| `detectFreeTextColumns(header)` | 設問名から自由記述列を特定（`【印象に残った言葉】`等） |
| `detectAwarenessColumn(header)` | 事前アンケートの認知度列を特定 |
| `isBrandUnaware(value)` | 認知度の回答が「未認知」かを判定 |
| `buildUnawareSet(preRows)` | メールアドレスをキーに未認知参加者の集合を作る |
| `majorityUnaware(emails, unawareSet)` | 言及者の過半が未認知か。同数はFALSE |
| `buildWorkshopSignalRows(words, unawareSet)` | ワード単位1行に整形 |

### `scripts/kizuki/workshop_extract.js`（読み取りのみ）

```
node scripts/kizuki/workshop_extract.js --post <sheet_id> [--pre <sheet_id>] > candidates.json
```

自由記述をLLMに渡して候補ワードを抽出し、事前の認知度を突合してJSONを出力する。
シートには一切書き込まない。

### `scripts/kizuki/workshop_seed.js`（書き込み）

```
node scripts/kizuki/workshop_seed.js candidates.json --case <case_id> --product <product_id> [--apply]
```

台帳と勉強会シグナルに登録する。既にデータ行があれば中断（重複防止）。

## 織り込む失敗モード

| 失敗モード | 対処 |
|---|---|
| **認知度の選択肢文言が想定と違う** | 現在回答0件で実物が見えない。部分一致リストで判定しつつ、**実際に出現した値を必ずログに出す**。8/22後に選択肢を見て調整できるようにする |
| **事前アンケートが無い／未提出者がいる** | 事前が無ければ全て `FALSE` として警告。未提出者は未認知集合に入れないが、過半判定の分母には言及者全員を使う |
| **名簿行・空行** | 自由記述列に1つも回答が無い行は回答者に数えない（Pamun版と同じ対策） |
| **過半判定の境界** | 2人中1人は `FALSE`、3人中2人は `TRUE`。テストで固定する |

## やらないこと

- Googleフォームの自動生成（Forms API 未有効）
- ワード単位の購買意向の算出（Track A の担当。このフォームには per-word の意向設問が無い）
- `アンケ評価` 列の自動埋め（採点に使われず、意味が定まっていない）

## 1. 背景・目的

`pamun.jp`（美容モニター/UGCサービス「Pamun」のLP）に対して、以下2つの改善ループを新設する:

1. **LPの高速改善サイクル** — Claudeに指示してLPデザインを簡単に変更し、staging確認→本番反映する
2. **広告クリエイティブ量産** — GA・広告媒体の数値から勝ちパターンを抽出し、新規バナーを量産する

これらを既存のCGデータ基盤（BigQuery）と地続きに構築し、広告→LP→数値→次の施策、というグロースループを回せる状態にする。

## 2. 確定した前提・決定事項

| 項目 | 決定 | 備考 |
|------|------|------|
| 対象サイト | `pamun.jp`（WordPress + TCD市販テーマ） | 美容モニター/UGCサービスLP。トップはコーポサイト |
| インフラ現状 | レンタルサーバーにファイルアクセス可・サブドメイン発行可 | TCDテーマはコード改変しづらく拡張性が低い |
| アーキ方針 | **B案ハイブリッド** | コーポトップはWPのまま／**広告用キャンペーンLPだけコードベース化** |
| LPスタック | **Astro + Firebase Hosting** | コンポーネント再利用でLP量産しやすい・完全静的で高速 |
| staging | **Firebase プレビューチャンネル** | PR/デプロイごとに一時URLを自動発行＝stagingが標準機能で得られる |
| バナー量産 | **Claudeが HTML/SVG生成 → ヘッドレスブラウザで各媒体規定サイズのPNG自動書き出し** | コピー・配色・構成違いを大量に量産 |
| データ集約 | 既存 **BigQuery（cg_analytics）** に統合 | ARCHITECTURE.md準拠 |

### アーキテクチャ選定の経緯（後戻り防止のため記録）
- **A案（WP/TCDのまま）**: 最速・低リスクだが、Claudeの自由度が「CSS微調整」止まりでLP量産・刷新ができない → 却下
- **B案（ハイブリッド）★採用**: 広告受け皿LPだけコード化。量産・ABテストが自由、既存トップ資産は維持。二重管理が発生するが目的に最も合致
- **C案（全面コード移行）**: 自由度最大だが移行コスト・SEO毀損リスク大 → 今回スコープ外（YAGNI）

## 4. サブシステム定義

### ① 制作・配信基盤 【最初に着手・土台】
- Astroリポジトリ ＋ Firebase Hosting
- Firebaseプレビューチャンネルで「PRごとに一時staging URL自動発行 → 承認で本番反映」
- 本番ドメイン `lp.pamun.jp`（サブドメイン、DNS設定）。既存WPトップとは共存
- LPのコンポーネント/テンプレート設計（ヒーロー・訴求・FAQ・CTA等の再利用部品）
- **これ単体でも「Claudeで作った高速LPを公開できる」価値が出る**

### ② 計測・データ基盤
- GA4 ＋ GTM を各LPに設置
- Google Ads / Meta Ads(FB/IG) / TikTok Ads アカウントと接続
- GA4 → BigQuery はネイティブ連携、広告媒体は日次でBigQueryへ（GAS or ネイティブコネクタ）
- LP別の CVR / 流入 / 離脱 を可視化（`lp_cvr_summary` 等の集計）

### ③ Claude駆動LP改善フロー
- 「Claudeに指示 → Astro編集 → preview URLで確認 → 承認で本番」の運用サイクル化
- ②の数値を根拠に改善を回す（勝ち/負けの判断ルール）
- リポジトリの運用ルール（CLAUDE.md相当）・ABテストの回し方を整備

### ④ バナークリエイティブ量産
- ②の数値から勝ちパターン（訴求軸・配色・構成）を抽出
- ClaudeがHTML/SVGでバナーを生成 → ヘッドレスブラウザ（Playwright等）で各媒体規定サイズのPNGを量産
- ブランドガイド（フォント・配色・トンマナ）をテンプレ化 → 広告入稿

## 5. 実装順序（積み上げ）

```
① 制作・配信基盤  ←★ 最初のサブプロジェクト（単体で価値が出る）
   ↓
② 計測基盤（①のLPに計測を載せる）
   ↓
③ 改善フロー運用化（①②が揃って回り始める）
   ↓
④ バナー量産（②の数値が溜まってから本領発揮）
```

各サブシステムは個別に `spec → plan → 実装` を回す。まず **① 制作・配信基盤** を次のブレストで詳細設計する。

## 6. 各サブプロジェクトで詰める未決事項（現時点で保留）

- **① 共通**: Firebaseプロジェクトの用意 / `lp.pamun.jp` のDNS設定権限 / Astroのコンポーネント設計方針

- **④**: バナー対象媒体・サイズ規定 / ブランドガイド（フォント・配色）/ 訴求パターンの元データ / ヘッドレス書き出しの実装手段

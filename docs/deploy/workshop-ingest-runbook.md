# 勉強会 → 気づきワード台帳 手順書

対象: アベンヌ勉強会（2026-08-22）ほか、以降の勉強会案件すべて
スクリプト: `scripts/kizuki/workshop_extract.js` / `scripts/kizuki/workshop_seed.js`
設計: [勉強会アンケート取込 設計書](../superpowers/specs/2026-08-17-kizuki-word-cycle-workshop-ingest.md)
関連: [Pamun取込 手順書](phase3-slice2-pamun-ingest-runbook.md)

勉強会が**気づきワードの本来の起点**。ここで発掘したワードを、あとで Pamun（Track A/B）や
広告で検証していく。**この日のアンケートが取れないと、以降の全工程に材料が無い。**

## 全体の流れ

```
1週間前   フォームの点検（設問名・選択肢・メール収集）
   ↓
前日まで   事前アンケートを回収 ── 認知度 → ブランド未認知の判定材料
   ↓
当日       勉強会 → その場で事後アンケートを回収 ── 自由記述が唯一のワード源泉
   ↓
翌日       workshop_extract → candidates.json を確認・編集 → workshop_seed
   ↓
その後     status=モニターにして Track A で検証（Pamun事後アンケートに3択を組み込む）
```

## Phase 1. 1週間前 — フォームの点検

### 1-1. 自由記述4問の設問名を変えない

候補ワードの源泉はこの4問。**設問名の見出し語でスクリプトが列を特定する**ので、
`【】` の中の文言を変えると検出できなくなる。

| 見出し語 | 役割 |
|---|---|
| `【最も印象が変わった点】` | 認識変化 |
| `【説明後に初めて理解できたこと】` | 認識変化 |
| `【印象に残った言葉】` | **主源泉**（抽出時に最も重視される） |
| `【使いたい部位・場面】` | 使用シーン軸 |

設問文の後半（説明文）は自由に変えてよい。**変えてはいけないのは `【】` の中だけ。**

> 設問を増やす場合、`lib/kizuki/workshop-ingest.js` の `FREE_TEXT_LABELS` に見出し語を足す。

### 1-2. 認知度の選択肢を控える

事前アンケートの認知度設問（`…どの程度ご存知だったか`）の**選択肢の文言を控えておく**。
「未認知」の判定は文言の部分一致で行っており、既定は次のとおり。

```
知らなかった / 知らない / 初めて / 聞いたことがない / 未認知
```

選択肢がこれに引っかからない言い回し（例:「まったく認識がなかった」）なら、
`lib/kizuki/workshop-ingest.js` の `UNAWARE_PATTERNS` に追加する。
**事前に直しておくのが望ましいが、当日以降でも直せる**（Phase 4 で実際の値がログに出る）。

### 1-3. メールアドレスの収集が有効か

**事前と事後は「メールアドレス」で突合する。** これが取れないと `ブランド未認知` が全て FALSE になる。

- 両フォームで「メールアドレスを収集する」が有効になっていること
- 参加者に**両方とも同じアカウントで回答**してもらうこと（案内文に明記）

### 1-4. 回答シートのIDを控える

フォーム編集画面 →「回答」→ スプレッドシートのアイコン、で回答シートが開く。URL の
`/spreadsheets/d/<ここ>/edit` がシートID。

## Phase 2. 前日まで — 事前アンケートの回収

**未提出者は「未認知」集合に入らない**（＝認知済み扱いになる）。
`ブランド未認知` は言及者の**過半**で判定するので、未提出が多いとフラグが立ちにくくなり、
workshop スコアが実際より低く出る。**全員回収を目指す。**

回収状況は回答シートを見れば分かる。

---

## Phase 3. 当日 — 事後アンケートの回収

### ここが一番重要

**自由記述がそのまま気づきワードになる。** 選択式の設問からはワードは生まれない。

- **その場で回答してもらう。** 後日回収に回すと回収率が落ち、材料が減る
- **自由記述を空欄にしない。** 特に【印象に残った言葉】。一言でもよいので書いてもらう
- **事前と同じメールアドレス**で回答してもらう

> ⚠️ **自由記述4問が全て空の回答は、回答者として数えられない**（名簿行と区別できないため）。
> 選択式だけ答えて自由記述を飛ばした人は、分母にも入らない。

### 回答率の目安

回答者数がそのまま `n` になり、言及数の意味を決める。参加者20人で回答18人なら n=18。
「何人中何人が言った言葉か」が訴求の強さの根拠になるので、**回答率がそのまま指標の質になる。**

## Phase 4. 翌日 — 取込

### 4-1. 準備

```bash
cd /Users/yuttyo/claude/creativegroup-dashboard
export SHEET_ID=1VxAOesBm_gi_jlSlq39FDtTMZNYOQcBm3J53gw3_g3o
```

ADC がなりすまし構成でログイン済みであること（[Pamun手順書 Step 2](phase3-slice2-pamun-ingest-runbook.md)）。

### 4-2. 候補ワードを抽出する

```bash
node .worktrees/kizuki-word-cycle/scripts/kizuki/workshop_extract.js \
  --post 1OJQSBLgx0J0ZVrKGi_7Q4PXojuAzJTQ6e6nb88PAmpk \
  --pre  1BDRR9d_RPXNpgmWz7tBllCkPkrZSfusA4VLNUDIKay0 \
  > candidates.json
```

シートには書き込まない。標準エラーに次が出る。**ここを必ず読む。**

```
自由記述の設問: 最も印象が変わった点 / 説明後に初めて理解できたこと / 印象に残った言葉 / 使いたい部位・場面
回答者: 18人
認知度の回答値: 「まったく知らなかった」=未認知 / 「名前は知っていた」 / 「使ったことがある」
未認知と判定した参加者: 7人
候補ワード: 11件
```

**確認すること:**

| 行 | 見るポイント |
|---|---|
| 自由記述の設問 | **4問すべて出ているか**。欠けていたら設問名が変わっている |
| 回答者 | 実際の回答数と合っているか。少なければ自由記述が空の人がいる |
| 認知度の回答値 | 「未認知」とすべき選択肢に `=未認知` が付いているか |
| 未認知と判定した参加者 | 0人なら判定が効いていない（`UNAWARE_PATTERNS` を直す） |

### 4-3. candidates.json を確認・編集する

**ここが人のレビューポイント。** ワードの文言はここで直す。不要なワードは配列から削除してよい。

```json
{
  "respondents": 18,
  "unaware": ["a@example.com", "..."],
  "words": [
    { "word": "肌が生き返る感じがする", "axis": "効能",
      "quote": "肌が生き返る", "mentionedBy": ["a@example.com", "b@example.com"] }
  ]
}
```

- `word` — 広告コピーの種になる言い回しか。要約文になっていたら直す
- `axis` — `効能 / 情緒 / 使用シーン / 成分 / 価格` のいずれか
- `quote` — 根拠になった実際の記述。**改変しない**
- `mentionedBy` — 言及数と `ブランド未認知` の判定に使う。**消さない**

### 4-4. 台帳と勉強会シグナルに登録する

まず書き込みなしで確認する。

```bash
node .worktrees/kizuki-word-cycle/scripts/kizuki/workshop_seed.js candidates.json \
  --case 2026-08-AVENE-CICA --product CICA
```

```
case=2026-08-AVENE-CICA / 候補ワード 11件 / 回答者 18人
採番: w016 〜 w026

word_id  言及  未認知  ワード
w016       9  TRUE    肌が生き返る感じがする
w017       5  FALSE   お守りとして持ち歩ける
...
```

内容がよければ `--apply` を付けて再実行する。

> **`word_id` は台帳全体で一意に自動採番される。手で番号を決めないこと。**
> `aggregateSignals` はシグナルを `word_id` だけで突合し case では絞らないため、
> 別案件で同じIDを振ると**別案件のシグナルが混ざる**。

> 同じ `--case` に既にデータがあると中断する（重複登録の防止）。
> やり直す場合は台帳から該当行を削除してから再実行する。

### 4-5. スコアに反映する

```bash
node .worktrees/kizuki-word-cycle/scripts/kizuki/recalc_job.js
```

BigQuery が未整備でも台帳の再計算は走る（広告取込はスキップされ、終了コードは1になる）。

## Phase 5. 検証フェーズへ引き継ぐ

勉強会だけでは**ワード単位の購買意向は測れない**（後述）。Track A で測る。

1. 台帳で検証したいワードの **status を「モニター」に**（5〜8件）
2. 設問を出す

```bash
node .worktrees/kizuki-word-cycle/scripts/kizuki/tracka_questions.js --case 2026-08-AVENE-CICA
```

3. 出力を次の Pamun 事後アンケートフォームに貼る（**末尾の `[wNNN]` は消さない**）
4. 回答後 `tracka_ingest.js` で取り込む

詳細は [Pamun取込 手順書の Track A 節](phase3-slice2-pamun-ingest-runbook.md)。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| `自由記述の設問列が見つかりません` | 設問名の `【】` の中が変わった | フォームを戻すか `FREE_TEXT_LABELS` に追加 |
| 自由記述の設問が4問未満しか出ない | 同上（一部だけ変わった） | 出ていない設問名を確認 |
| `回答が0件です` | 自由記述が全員空、または回答シートが違う | シートIDとタブ名を確認 |
| 回答者数が実際より少ない | 自由記述を全て空欄で出した人がいる | 仕様どおり。分母に入れたいなら手で追記してもらう |
| `未認知と判定した参加者: 0人` | 選択肢の文言が `UNAWARE_PATTERNS` に無い | ログの「認知度の回答値」を見てパターンを追加 |
| `⚠ 事前アンケートに認知度の設問が見つかりません` | 設問文に「認知」「ご存知」が無い | `AWARENESS_KEYWORDS` に追加 |
| ブランド未認知が全て FALSE | 事前未回収、またはメール不一致 | 事前の回収状況とメールの綴りを確認 |
| `既に N 行あります` | 同じ case で既に登録済み | 台帳から該当 case の行を削除してから再実行 |
| 台帳のスコアが全て0 | シグナルが勉強会しか無い | 正常。Track A / 広告が入ると上がる |

## この導線が測れないもの

勉強会フォームの【購入意向】【推奨意向】は**商品全体に対する1問**で、ワード単位ではない。
したがって**ワードごとの購買意向共感率はこのフォームからは出ない**。それは Track A の担当。

勉強会が担うのは候補ワードの発掘と、`言及数`・`ブランド未認知` の2つのシグナル
（スコアエンジンが勉強会シグナルから使うのはこの2つだけ）。
